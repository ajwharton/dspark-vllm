# PIP-201 — Cold-start reasoning garble / thinking-routing (M2, trap 04/20)

## Capability
Ensure DeepSeek-V4-Flash DS4F reasoning survives cold start and multi-turn
resend, and that thinking is routed correctly (never leaked into plain content,
never silently dropped on conversation resend). Ties to trap 04/20.

## Evidence (measured, 2026-08-12, temper single-node DS4F-0731)
- Harness reasoning gate: `reasoning present in 3/3 turns`, exit 0 — reasoning
  is preserved across resend when thinking is requested.
- Probing showed the structured `reasoning` field appears ONLY with explicit
  `chat_template_kwargs.enable_thinking=true`. The `-think` alias alone did NOT
  force it; without the toggle the thought stays inline in `content`.
- Fork/Moet docs warn 0731 is agent-tuned and "reopens thinking mid-answer",
  which used to leak raw thinking to clients; `VLLM_DS_V3_LEGACY_REASONING=1`
  restores stock (legacy) behavior.

## Root need
A client that gates DS4F must be able to request thinking explicitly, and the
server/template must route every thinking block to the `reasoning` field
predictably. This is not a model-capability gap — it is a request-routing gap.

## Deliverables (extracted against the chosen base)
1. Client capability to request thinking per-request (`enable_thinking`). —
   DONE as harness `VLLMClient` `chat_template_kwargs` + CLI `--think`
   (committed, 0d04396, 12/12 tests).
2. Server/template wiring so a per-request thinking toggle is honored and all
   thinking blocks route to `reasoning` (not leaked to content). — port in.
3. Cold-start validation: first-turn clean on cold start.

## Acceptance (NO-NERF-GATE)
- `harness.cli reasoning` returns reasoning present N/N (exit 0).
- First-turn content clean on cold start (no garbled or re-opened thinking in
  `content`).
- Decode not regressed.
